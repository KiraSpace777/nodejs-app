# ==== MODULE 4 (Аутентифікація) ====

У цьому модулі ми розглянемо основи безпеки веб-додатків, зосередившись на аутентифікації та авторизації користувачів. Ми розберемо, як працює реєстрація, як безпечно зберігати паролі, що таке сесії та токени доступу, і чому це все критично для будь-якого сучасного застосунку.

У цифровому світі діють ті ж правила. Щоб отримати доступ до ресурсу, потрібно підтвердити, що ви дійсно його власник — через паролі, ключі доступу або інші засоби ідентифікації.

### Користувач

Зазвичай ми уявляємо користувача як людину. Але в інформаційних системах користувачем може бути й інша система.
Наприклад:
використання API-ключів для доступу до сторонніх сервісів;
взаємодія нашого бекенду з MongoDB — це теж приклад «користувач ↔ система».

### Регулятор (authority)

У реальному світі ідентичність підтверджує держава. У цифровому — цю роль виконує бекенд, тобто наш сервер. Він є «регулятором», який встановлює, хто ви, і вирішує, які ресурси вам доступні.
Тому аутентифікація та авторизація — це ключові механізми. Саме від них залежить безпека даних користувачів, а отже і довіра до вашого застосунку.

### Доступ до ресурсів

Ключі від квартири чи машини обмежують стороннім можливість користуватися вашою власністю. У світі IT цю роль виконують:
паролі,
seed-фрази,
електронні ключі.
Вони є «пропуском» до ваших даних і сервісів.

### Посвідчення ідентичності

Машину можуть вкрасти, але наявність документів підтвердить право власності. У цифровому світі є свої механізми:
відновлення пароля через пошту або телефон;
MFA (мультифакторна аутентифікація), де ви підтверджуєте себе одразу кількома способами.
Це додатковий рівень захисту, який робить систему надійнішою.

### Аутентифікація

Аутентифікація — це процес перевірки ідентичності користувача або системи, яка намагається отримати доступ до ресурсу.
Іншими словами, ми перевіряємо: «Чи дійсно ця людина (або програма) є тим, за кого вона себе видає?»
У нашому випадку — це означає, що система знаходить користувача за унікальним ідентифікатором (наприклад, email) і перевіряє, чи надані ним облікові дані (наприклад, пароль) правильні.

#### Етапи аутентифікації

1. Представлення ідентифікатора
   Користувач подає свій унікальний ідентифікатор. У нашому додатку це буде email.
   Важливо: два користувачі з однаковим email у системі існувати не можуть. У багатьох системах після реєстрації email не можна змінити.

2. Представлення облікових даних
   Разом з ідентифікатором подаються «ключі доступу» — пароль, ssh-ключ, seed-фраза тощо.
   Якщо ви працювали з криптогаманцями, то знаєте seed-фразу — набір слів, який відкриває доступ до ваших коштів.

3. Перевірка
   Система порівнює надані дані з тими, що збережені у базі. Якщо все збігається — користувач підтверджується.

4. Надання доступу
   Після успішної перевірки користувач отримує доступ.
   Це може бути реалізовано через:
   створення сесії (ідентифікатор у cookie);
   токен доступу (наприклад, JWT).

5. Керування сеансом
   У багатьох системах визначається, як довго користувач залишається «залогіненим». Це може бути кілька хвилин, годин чи днів — залежно від політики безпеки.

### Авторизація

Авторизація — це наступний крок після аутентифікації.
Вона визначає, що саме користувач може робити у системі.
Тобто: якщо аутентифікація відповідає на питання «Хто ви?», то авторизація відповідає на питання «Що вам дозволено?».

#### Основні аспекти авторизації

Права доступу: визначається, до яких ресурсів чи функцій користувач має доступ.
Ролі та привілеї: користувач може належати до ролі (наприклад, «адмін», «користувач»), і ця роль визначає його можливості.
Управління правами: права можуть змінюватися динамічно — наприклад, адміністратор може відкрити чи закрити доступ у будь-який момент.
Відмова у доступі: якщо користувач намагається зробити те, на що прав немає — система повинна повернути помилку доступу.
Аудит і логування: дії користувачів логуються, щоб можна було відстежити підозрілі або несанкціоновані дії.

Приклад
Уявімо вебсайт із системою доступу:
Користувач логіниться (аутентифікація).
Система перевіряє його email і пароль.
Після цього визначається його роль:
адміністратор має доступ до адмін-панелі;
звичайний користувач може лише переглядати сторінки й залишати коментарі.

Як запам’ятати різницю
Мнемоніка проста:

### Аутентифікація → «ти існуєш у системі».

### Авторизація → «яка у тебе роль і що тобі дозволено».

### === (4.20) Middleware аутентифікації / Middleware authenticate

// src/middleware/authenticate.js

Ми вже створили механізм сесій, токенів і cookies. Наступним кроком є контроль доступу до наших даних. У реальних застосунках є приватні дані — ті, що не повинні бути доступні будь-кому. Наприклад:

Щоб обмежити доступ до приватних колекцій, ми створимо middleware authenticate, який перевірятиме токени у cookies і визначатиме, чи користувач може виконати запит.

### === (4.21) Middleware аутентифікації / Використання у маршрутах

// src/routes/studentsRoutes.js

Тепер ми можемо скористатись нашим middleware authenticate в роутері для запитів до колекції студентів
Коли ми приміняємо middleware таким чином router.use(path, middleware), вона буде застосовуватися до всіх роутів цього роутера. Тобто, вона відпрацює на всіх роутах, що починаються зі /students.

### === Висновок

Middleware authenticate виконує роль «охоронця» приватних даних.
Він перевіряє токени, сесію та користувача.
Якщо перевірка успішна — доступ до колекції студентів відкривається.
Якщо ні — користувач отримує відповідь з 401 Unauthorized.
Таким чином ми забезпечуємо безпечний доступ до наших даних: працювати з колекцією студентів можуть тільки ті користувачі, що пройшли аутентифікацію.

## Фільтрація в MongoDB

У MongoDB ми можемо накладати умови за допомогою спеціальних операторів.

Приклад: знайти студентів, у яких середній бал від 10 і вище:

```javascript
db.students.find({ avgMark: { $gte: 10 } });
```

Тут $gte означає greater than or equal (більше або дорівнює).

### Основні оператори в Mongoose

У Mongoose ці оператори працюють так само. Ось кілька прикладів:

### 1. Рівність ($eq)

```javascript
Student.find({ age: { $eq: 9 } });
```

Знаходимо студентів з віком 9.

### 2. Нерівність ($ne)

```javascript
Student.find({ avgMark: { $ne: 10 } });
```

Знаходимо студентів, у яких середній бал не дорівнює 10.

### 3. Більше ($gt), Більше або дорівнює ($gte)

```javascript
Student.find({ age: { $gt: 8 } });
```

Знаходимо студентів з віком більше 8.

### 4. Менше ($lt), Менше або дорівнює ($lte)

```javascript
Student.find({ avgMark: { $lte: 8.5 } });
```

Знаходимо студентів із середнім балом не вищим за 8.5.

### 5. У межах списку ($in)

```javascript
Student.find({ gender: { $in: ['male', 'female'] } });
```

Знаходимо студентів чоловічої або жіночої статі.

### 6. Не у списку ($nin)

```javascript
Student.find({ gender: { $nin: ['male'] } });
```

Знаходимо всіх студентів, крім чоловіків.

## Query Builder у Mongoose

У Mongoose є зручний механізм побудови складних запитів — Query Builder. Він дозволяє будувати умови покроково, додаючи фільтри «ланцюжком».

Приклад:

```javascript
await Student.find()
  .where('age')
  .gte(6)
  .lte(10) // вік від 6 до 10 включно
  .where('avgMark')
  .gt(7) // середній бал більше 7
  .exec();
```

Що тут відбувається:
.where('age').gte(6).lte(10) → додаємо умову для віку;
.where('avgMark').gt(7) → додаємо умову для середнього балу;
.exec() → виконує зібраний запит.

Таким чином, ми отримаємо студентів, яким від 6 до 10 років, і які мають середній бал вище 7.

Завдяки фільтрації ми можемо швидко працювати навіть із великими колекціями, отримуючи лише ті дані, які нам потрібні.

## Індекси у MongoDB

Коли ми працюємо з великою базою даних, дуже важливо швидко знаходити потрібні записи. Для цього використовуються індекси.

Уяви, що в тебе є книга на 500 сторінок, і ти хочеш знайти слово “React”.
Без індексу ти мусиш перегорнути всі сторінки одну за одною.
З індексом ти відкриваєш перелік слів у кінці книги й одразу бачиш, на якій сторінці це слово знаходиться.

У MongoDB працює той самий принцип: індекс — це окремий структурований список (B-tree), який значно прискорює пошук.

Без індексу MongoDB виконує COLLSCAN — перегляд усіх документів один за одним. При кількох тисячах документів це ще терпимо, але при десятках чи сотнях тисяч — запит стає дуже повільним.

З індексом MongoDB використовує IXSCAN — швидкий пошук по дереву індексів.

Індекс — це “словник” значень поля. База шукає по цьому словнику, а не перебирає всю колекцію.

## Сортування

Сортування даних — одна з базових операцій у будь-якому застосунку. Воно дозволяє впорядкувати записи в певному порядку: наприклад, показати студентів від наймолодших до найстарших, або відсортувати за середнім балом.

### Основні принципи сортування

Поле сортування — визначає, за яким атрибутом (полем) проводиться сортування. У нашому випадку це можуть бути name, age, avgMark.
Порядок сортування — напрямок:
зростання (ASC / ascending / 1) — від меншого до більшого;
спадання (DESC / descending / -1) — від більшого до меншого.

Сортування краще виконувати безпосередньо у базі даних, а не в коді фронтенда. Mongoose (і MongoDB під капотом) має оптимізовані методи для цього, тому результат буде швидший і ефективніший.

### Синтаксис у Mongoose

Метод sort() у Mongoose дозволяє вказати кілька полів і напрямків сортування.

```javascript
Model.find().sort({ field1: direction1, field2: direction2 });
```

field1, field2 — назви полів, за якими проводиться сортування;
direction1, direction2 — напрямок сортування.

#### Варіанти напрямків:

```javascript
1, "asc", "ascending" → сортування за зростанням (від меншого до більшого);
1, "desc", "descending" → сортування за спаданням (від більшого до меншого).
```

#### Приклади:

```javascript
// За віком зростанням
Student.find().sort({ age: 1 });

// За середнім балом спаданням
Student.find().sort({ avgMark: 'desc' });

// Комбіноване сортування: спочатку за gender зростанням, потім за age спаданням
Student.find().sort({ gender: 'asc', age: -1 });
```

## ==== 5 - Модуль fs ====

Одна з головних можливостей Node.js — робота з файлами та папками. Для цього використовується вбудований модуль fs.

Багато його методів існують у двох варіантах:
**_ синхронні (readFileSync, writeFileSync), які блокують виконання коду;
_** асинхронні (через fs/promises), які працюють із Promise і не блокують.

Синхронні методи іноді зручно застосувати, наприклад, щоб один раз зчитати конфігурацію на старті програми. У більшості випадків краще використовувати асинхронні версії.

## ==== Читання файлу - fs ====

### // ------ fs.readFileSync(path, options)

— синхронне читання вмісту файла. Приймає шлях до файлу та, за потреби, кодування ("utf8", "ascii" тощо). Якщо кодування не вказано, повертає Buffer, якщо вказано — звичайний рядок.

```javascript
// import fs from "node:fs";

// === приклад без кодування
const buffer = fs.readFileSync('file.txt');
console.log(buffer); // <Buffer 48 65 6c 6c 6f ...>

// == приклад із кодуванням
const data = fs.readFileSync('file.txt', 'utf8');
console.log('Вміст файлу:', data); // "Hello"
```

### // ------ fs.readFile(path, options)

— асинхронне читання вмісту файла. Приймає шлях і опції. Повертає Promise, який у разі успіху містить або Buffer, або рядок (залежно від того, чи вказано кодування).

```javascript
import fs from 'node:fs/promises';

// без кодування
const buffer = await fs.readFile('file.txt');
console.log(buffer); // <Buffer ... >

// з кодуванням

const data = await fs.readFile('file.txt', 'utf8');
console.log('Вміст файлу:', data); // "Hello"
```

У Node.js Buffer — це спеціальний тип даних для зберігання двійкової інформації (наприклад, вмісту файлів). Якщо потрібно працювати з текстом, достатньо вказати кодування, і тоді результатом буде звичайний рядок.

## ==== Тип даних Buffer ====

При роботі з файловою системою ви часто будете бачити об’єкти типу Buffer. Це спеціальний тип даних у Node.js, призначений для роботи з двійковими даними.

Біт — це найменша одиниця інформації: 0 або 1.
Байт — це 8 бітів. У такій комбінації можна представити 256 різних значень.

Buffer у Node.js — це масив байтів. Кожен байт може зберігати невелике значення (наприклад, код символу).

```javascript
import fs from 'node:fs/promises';
const buffer = await fs.readFile('hello.txt');

// якщо у файлі hello.txt був текст "Hello World!"
console.log(buffer);
// <Buffer 48 65 6c 6c 6f 20 57 6f 72 6c 64 21>
```

Вивід <Buffer ...> показує набір байтів у шістнадцятковій системі (hex). Кожен байт відповідає одному символу або службовому знаку (наприклад, пробілу).

## ==== Кодування ====

Файл завжди зберігається як набір байтів. Але щоб інтерпретувати його вміст як текст, потрібно знати кодування. Найпоширеніше текстове кодування — UTF-8. Саме воно дозволяє перетворити байти у символи:

```javascript
import fs from 'node:fs/promises';

const buffer = await fs.readFile('hello.txt');
console.log(buffer.toString('utf-8')); // Hello World!
```

Якщо при читанні файлу одразу вказати кодування ("utf8"), результатом буде рядок, а не Buffer. Якщо кодування не вказано — повертається Buffer.
